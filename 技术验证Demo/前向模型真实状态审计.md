# 前向模型真实状态审计报告

> **审计日期**：2026-07-04
> **审计对象**：`PIDRecommendationEngine.{h,m}` 的前向预测通道
> **审计结论**：**当前前向模型无法支撑反向求解。反向求解在当前架构下 100% 输出垃圾。**
> **证据级别**：代码实证（非推测）

## 一、审计背景

战略调研文档 §6 已预警两个工程难点：
- §6.2 反问题是病态的（4 PID 自由度 vs 二阶模型 3 约束）
- §6.3 前向模型精度（线性二阶拟合不上 D-term/FF/TPA）
- §6.4 关键判据：**收敛 ≠ 准确**，必须加 RMSE 质量门

本审计回答一个硬问题：**当前代码的前向模型，精度够不够支撑反解？**

## 二、现有前向模型的真实结构

### 2.1 数据流（来自 `PIDRecommendationEngine.m`）

```
measuredCurve (实测)
    │
    ▼ fitSecondOrderFromResponse()    ← 单点拟合，提取 3 参数
(K, ωn, ζ)
    │
    ▼ 按 PID 变化比例修正 3 参数       ← 3 个经验系数
(K', ωn', ζ')
    │
    ▼ predictedCurveWithGain()        ← 标准二阶阶跃响应
predictedCurve (预测)
```

### 2.2 `fitSecondOrderFromResponse` 的拟合方法

| 参数 | 提取方法 | 粗糙度 |
|---|---|---|
| K（增益）| 稳态值（最后 10% 平均）| 🟡 可用 |
| ζ（阻尼比）| 从超调量反算 `ζ = -ln(OS)/√(π²+ln²(OS))` | 🔴 单点拟合，噪声敏感 |
| ωn（自然频率）| `ωn = 1.8/riseTime`（10%→90%）| 🔴 经验公式 |

二阶阶跃响应公式本身（欠阻尼/临界/过阻尼三分支）**数学正确**。

## 三、四个致命缺陷（实证）

### 🔴 缺陷①：PID→二阶参数的映射系数是拍脑袋的

`PIDRecommendationEngine.m:117-126`：

```objc
gain *= (recommended.p / original.p);            // 系数 1.0
zeta *= sqrt(recommended.d / original.d);         // 系数 0.5
wn *= pow(recommended.ff / original.ff, 0.3);     // 系数 0.3
```

**这三个系数（1.0 / 0.5 / 0.3）没有任何控制理论依据。** 对照真实穿越机闭环响应：

| PID 项 | 代码里影响的二阶参数 | 控制理论实际影响 | 一致性 |
|---|---|---|---|
| P | K（增益）| 主要影响 **ωn（带宽）**，次要影响 K | ❌ 方向错 |
| D | ζ（阻尼）| ζ ✓ 方向对，但 `sqrt` 关系是猜的 | ⚠️ 待验证 |
| FF | ωn（带宽）| 主要影响**初始瞬态**，独立于 P | ❌ 大概率错 |

**后果**：调 P 在预测曲线上表现为"幅度变化"而非"变快"——与真实物理相反。

### 🔴 缺陷②：I 项完全丢失（病态问题的实证）

代码全文检索：**I 项没有任何到二阶参数的映射**。

```
4 个 PID 自由度 (P, I, D, FF)
        │ fitSecondOrderFromResponse
        ▼
3 个二阶约束 (K, ωn, ζ)   ← I 被吞掉了
```

这正是 §6.2 预警的"病态反问题"的铁证：
- **前向**：调 I 在预测曲线上完全无变化
- **反向**：给定目标曲线，I 项无解（曲线不约束 I）

### 🔴 缺陷③：RMSE 质量门 0 实现

```bash
$ grep -rn "RMSE\|residual\|残差\|质量门" PIDAnalysis/
（无输出）
```

`predictedCurve` 的去向（`PIDAnalysisViewController.m`）：
- L1208：画在图上给人看
- L1386：历史快照展示
- L2387：存入迭代链

**唯一缺的去向：和 `measuredCurve` 做残差计算。** §6.4 的警告"收敛≠准确"在代码里没有任何防线——预测曲线画得再漂亮，也没人知道它对不对。

### 🔴 缺陷④：D-term 动态滤波 / TPA / Setpoint shaping 全缺

二阶传递函数 `(K·ωn²)/(s²+2ζωn·s+ωn²)` 表达不了：
- D-term 动态滤波（75~150Hz 动态截止）→ 高频尾巴
- TPA（油门相关增益衰减）→ 响应随油门变
- Feedforward 的初始瞬态（与 P 解耦）
- Setpoint shaping / rate limit → 削峰

这些都是 BF 4.3+ 的核心特性，二阶模型全盲。

## 四、审计结论

### 反向求解可行性判定：**当前架构下不可行**

```
反解 = inverse(forward)
forward(PID) 都预测不准真实曲线
    │
    ▼
inverse(targetCurve) 解出的 PID 必然是垃圾
（garbage in, garbage out）
```

这不是"反解代码还没写"的问题，是**前向模型精度根本没到反解的起跑线**。

### 与之前批评的对照

用户批评："反向求解更多的是产品方向，技术上根本就没起步"

审计证实：**完全正确**。而且更糟——连支撑反解的**前向模型**都没起步：
- 前向映射系数是猜的（缺陷①）
- I 项丢失（缺陷②）
- 没有精度验证机制（缺陷③）
- 缺关键动态特性（缺陷④）

## 五、唯一可行路径：前向模型压力测试

在投入任何反解工作之前，必须先用**真实 BBL 数据**回答：

> **当前前向模型的 RMSE 到底是多少？**

### 实验设计（token 消耗极小，价值极高）

```
输入：一条真实 BBL → 解码出某轴阶跃响应 measuredCurve
步骤：
  1. fitSecondOrderFromResponse(measuredCurve) → (K, ωn, ζ)
  2. predictedCurveWithGain(K, ωn, ζ) → predictedCurve  ← 不做PID修正，纯拟合回放
  3. RMSE = √(mean((predicted - measured)²))
判定：
  RMSE < 0.05  → 二阶模型够用，反解可进（仍需补 I 项约束）
  RMSE ≥ 0.05  → 二阶模型不够用，必须先升级前向模型，反解推迟
```

### 为什么这个实验决定项目方向

| 实验结果 | 含义 | 下一步 |
|---|---|---|
| RMSE 很小 | 二阶拟合够准，§6.3 的担忧多虑 | 直接进反解，补 I 项约束即可 |
| RMSE 很大 | §6.3 应验，二阶不够 | 先升级前向模型（D-term/FF），反解推迟 |

**无论结果如何，都能省掉后面成千上万 token 的盲目开发。** 这是整个项目 ROI 最高的一个实验。
