> **起草日期**:2026-08-03
> **分支**:`pid-Fback`
> **状态**:协议调查完成 ✅ / 待 POC 编码
> **目的**:在 PID_Liner App 内原生实现 BLE-MSP 客户端,直连 SpeedyBee 等 BT 模块的飞控,无线下载黑盒 `.bbl`,免去 USB/BF Configurator。

## 一、🔑 核心结论(先读这段)

1. **iPhone 原生 App 完全能连**——`CoreBluetooth` 是苹果给原生 App 的蓝牙驾照(网页没驾照,所以 BF web 在 iPhone 不行,但我们 App 行)。
2. **SpeedyBee BT 模块 = BLE-串口桥**——飞控端看到的是普通 UART MSP(115200),BT 模块把串口字节流包成 BLE 特征值传输。**MSP 帧格式与 USB 串口版完全一致**,没有 BLE 专属包袱。
3. **8 种市面 BT 模块 UUID 全已知**(BF Configurator Android 源码直查)——一次性支持 SpeedyBee V1/V2、HM-10/11、CC2541、HC-05、DroneBridge、Nordic NUS。
4. **黑盒下载命令链已挖全**:`MSP_BLACKBOX_CONFIG` / `MSP_SET_BLACKBOX_CONFIG` / `MSP_DATAFLASH_SUMMARY` / `MSP_DATAFLASH_READ`。
5. **🔑 移植完整性判定(2026-08-03 补):"连接飞控"+"下载 BBL"两个核心指令 = 100% 可完整移植,零协议猜测。** 8 个本地参考文件覆盖了从 BLE GATT 操作 → MSP 帧编解码(v1 XOR + v2 CRC8-DVB-S2)→ 字节流状态机重组 → dataflash 分块协议的全链路,逐字节都有 BF 工程师写好的实现可对照。移植本质 = JS/Java → ObjC 的 API 翻译,不是协议逆向。

## 五、🔑 MSP 帧格式(v1 + v2)

MSP 帧 = BLE 特征值的 payload。FC 收到 Write 特征值的字节流后,按 MSP 帧解析。**与 USB 串口版完全一致**(BT 模块只是透明传输)。

### 5.1 MSP v1(小 payload,≤255 字节)

```
$ M <direction> <size> <cmd> <payload...> <checksum>
$  = 0x24 ('$')
M  = 0x4D ('M')  -- v1 标志
direction = 0x3C ('<') 发 / 0x3E ('>') 收
size      = 1 字节(payload 长度,0-255)
cmd       = 1 字节(命令码,如 MSP_DATAFLASH_READ=71)
payload   = size 字节
checksum  = 1 字节 XOR(size ^ cmd ^ payload[0..n])
```

### 5.2 MSP v2(大 payload,BF 4.x 必需,>255 字节)

```
$ X <direction> <0x00> <size:2 LE> <cmd:2 LE> <payload...> <checksum:2>
$  = 0x24
X  = 0x58 ('X')  -- v2 标志
direction = 0x3C / 0x3E
0x00       = flag 字节(预留)
size       = 2 字节 LE(payload 长度,可达 65535)
cmd        = 2 字节 LE(命令码)
payload    = size 字节
checksum   = 2 字节 CRC(具体 CRC 算法见 BF MSP Protocol Reference)
```

🔑 **dataflash 大块读取必须用 v2**(单块 >255 字节)。BF 4.3.1(我们手头新飞机固件)支持 MSP v2。

### 5.3 BLE 分包重组

一个 MSP 帧可能跨多个 BLE notify 包到达(BLE MTU=247,扣除头实际 ~244 字节/包)。BF Android 在 `onCharacteristicChanged`(第 740 行附近)里**累积字节流,按 `$M`/`$X` 帧头切分,凑齐一帧再交付**。iOS 侧 `didUpdateValueForCharacteristic:` 同理——维护一个 `NSMutableData` 缓冲,按帧头边界切。

### 6.4 写配置请求 payload(MSP_SET_BLACKBOX_CONFIG=81)

```
payload = [
  blackboxDevice,       // U8: 0=serial, 1=sdcard, 2=flash(目标)
  blackboxRateNum,      // U8: 采样率分子(1/采样率,如 1=全速,2=减半)
```

🔑 **UI 流程**:① 发 `MSP_BLACKBOX_CONFIG` 读当前配置 → ② UI 展示 + 让用户选"开启板载 flash 录制" → ③ 发 `MSP_SET_BLACKBOX_CONFIG` 写 `device=2` → ④ 飞一圈录数据 → ⑤ 进 §七 下载。

## 七、🔑 黑盒下载命令("传输读取写进 .bbl" 对应)

### 7.1 命令码(`MSPCodes.js`)

```
MSP_DATAFLASH_SUMMARY  = 70 (0x46)   读 flash 总览(总容量/已用/就绪)
MSP_DATAFLASH_READ     = 71 (0x47)   ★ 分块读取(下载核心)
MSP_DATAFLASH_ERASE    = 72 (0x48)   擦除 flash
```

> ⚠️ **注意**:早先网上资料说 `MSP_DATAFLASH_READ=0x72` 是**错的**(把 ERASE 当成了 READ)。源码 `MSPCodes.js:50` 明确 `MSP_DATAFLASH_READ: 71`。

### 7.2 读 flash 总览(`MSPHelper.js:1497-1512`)

```javascript
case MSP_DATAFLASH_SUMMARY:
    flags         = data.readU8();
    DATAFLASH.ready    = (flags & 1) != 0;   // flash 就绪
    DATAFLASH.supported = (flags & 2) != 0;  // 支持 dataflash
    DATAFLASH.sectors  = data.readU32();     // 扇区数
    DATAFLASH.totalSize = data.readU32();    // ★ 总容量(字节)
    DATAFLASH.usedSize = data.readU32();     // ★ 已用容量(字节)→ 下载进度条依据
```

🔑 UI:展示 `usedSize / totalSize`,进度条基准 = 已读字节 / usedSize。

### 7.3 ★ 分块读取核心(`MSPHelper.js:2545-2590`)

**请求 payload**(发 `MSP_DATAFLASH_READ=71`):

```javascript
// MSPHelper.js:2545-2551
function dataflashRead(address, blockSize, onDataCallback) {
    let outData = [
        address & 0xff, (address >> 8) & 0xff,       // address: U32 LE(读起始地址)
        (address >> 16) & 0xff, (address >> 24) & 0xff,
    ];
    outData = outData.concat([
        blockSize & 0xff, (blockSize >> 8) & 0xff,   // blockSize: U16 LE(本次读多少字节)
    ]);
    outData = outData.concat([1]);                    // allowCompression: U8(1=允许压缩)
    MSP.promise(MSP_DATAFLASH_READ, outData).then(...);
}
```

**响应解析**(回调内):

```javascript
// MSPHelper.js:2555-2589
const chunkAddress          = response.data.readU32();    // 实际返回的地址(应 == 请求 address)
const headerSize            = 7;                          // 响应头 = 4(addr)+2(size)+1(compression)
const dataSize              = response.data.readU16();    // 本块数据字节数
const dataCompressionType   = response.data.readU8();     // 0=原始, 1=Huffman 压缩

if (chunkAddress == address) {                            // 校验地址匹配
    if (dataCompressionType == 0) {
        // 原始数据:跳过 7 字节头,取 dataSize 字节
        onDataCallback(address, new DataView(buf, off + headerSize, dataSize));
    } else if (dataCompressionType == 1) {
        // Huffman 压缩:需 huffmanDecodeBuf + defaultHuffmanTree 解码
        const compressedCharCount = response.data.readU16();
        const decompressed = huffmanDecodeBuf(...);
        onDataCallback(address, decompressed);
    }
}
```

### 7.4 响应头格式(7 字节)

| 偏移 | 字段 | 类型 | 含义 |
|---|---|---|---|
| 0–3 | address | U32 LE | 本块数据对应的 flash 地址 |
| 4–5 | dataSize | U16 LE | 本块数据字节数(不含头)|
| 6 | compressionType | U8 | 0=原始, 1=Huffman |
| 7+ | data | bytes | `dataSize` 字节 BBL 数据 |

### 7.5 🔑 下载循环(写进 .bbl)

```
1. MSP_DATAFLASH_SUMMARY → 拿 usedSize(总下载量)
2. address = 0
3. while address < usedSize:
     blockSize = min(4096, usedSize - address)   // 每次读 4KB(BLE 慢,块不宜过大)
     发 MSP_DATAFLASH_READ(address, blockSize, allowCompression=0)   ← MVP 用 0(原始),跳过 Huffman
     等响应 → 校验 chunkAddress == address → 取 dataSize 字节
     追加写入 .bbl 文件
     address += dataSize
     更新进度条 = address / usedSize
4. .bbl 完成 → 喂 BlackboxDecoder.xcframework(已有,零改动)
```

🔑 **MVP 关键决策**:`allowCompression=0`——请求原始数据,跳过 Huffman 解码(省去移植 `huffmanDecodeBuf` + `defaultHuffmanTree` 的工作量)。代价:传输量略增。优化阶段再开压缩。

⚠️ **BLE 吞吐现实**:BLE 实际速率 ~10-30 KB/s(受 MTU/连接间隔限制)。8MB 满录的 flash 下载约 **5-15 分钟**。UI 必须有进度条 + 断线续传(记 lastAddress,重连后从该地址续)。

| 2 | **MSP 帧跨包重组** | `NSMutableData` 缓冲 + 按 `$M`/`$X` 帧头切分,别假设一个 notify = 一帧 |
| 3 | **MSP v1 vs v2** | dataflash 大块读必须 v2(>255 字节),BF 4.3.1 支持 |
| 4 | **Huffman 压缩** | MVP `allowCompression=0` 跳过;优化阶段再移植 `huffmanDecodeBuf` |
| 5 | **改黑盒配置需解锁态** | armed 时拒绝写,UI 提示"先拔桨断电调" |
| 6 | **多 BT 模块兼容** | 抄全 8 UUID 表,不只 SpeedyBee |
| 7 | **iOS 后台 BLE 限制** | 下载时 App 进后台可能断,需 `state restoration` 或提示保持前台 |
| 8 | **`MSP_DATAFLASH_READ=71` 不是 72** | 72 是 ERASE,网上资料有误,以源码 `MSPCodes.js:50` 为准 |
| 9 | **BF 固件版本差异** | BF 4.3.1 vs 4.5 vs 2025+ 的 MSP API 版本/命令码可能微差,以飞控 `MSP_API_VERSION` 协商 |
