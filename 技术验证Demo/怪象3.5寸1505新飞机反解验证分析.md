## 四、详细结果

### 4.1 质量门（4 session 全过）

| Session | 原始点 | 曲线点（stackResponse） | 状态 |
|---|---|---|---|
| S1 | 100000 | 4000 | ✅ 最完整 |
| S2 | 92564 | 4000 | ✅ |
| S3 | 75043 | 4000 | ✅ |
| S4 | 55915 | 4000 | ✅ 后部砍但够（>16000 阈值） |

S2 归一化曲线（dump 见 `/tmp/spbe_s2_curve.txt`）：标准 S-curve 阶跃，0→1 平滑上升（~80 点到 0.9），稳态后小幅振荡（真实噪声），数据干净。

### 4.2 K 扫描（S2，真 P=45，FF=0 最干净，固定 τM=0.010/dScale=0.0007）

| K_plant | 反解P | 误差 | RMSE |
|---|---|---|---|
| 5 | 83.6 | 85.9% | 0.065 |
| **10** | **42.4** | **5.8%** | **0.063** ← 拟合最好 |
| 15 | 28.7 | 36.2% | 0.061 |
| 20 | 21.9 | 51.4% | 0.059 |
| 30 | 15.0 | 66.7% | 0.057 |
| 50（借用吴bbl） | 9.45 | 79.0% | 0.055 |
| **80** | **44.6** | **0.8%** ← P最准 | 0.113 |

🔑 **bestK=80**（P 误差最小 0.8%）。但 K=10 也接近（5.8%）—— **K 欠定**（见 §六 #27）。
🔑 **"最小 RMSE 选 K" 失效**：K=10 拟合最好（RMSE 0.063）但 P 偏 5.8%；K=80 P 最准但 RMSE 最差（0.113）。forward 不完美时，最佳拟合 K ≠ 真实 K。

### 4.3 bestK=80 重跑 4 session（核心结果）

| S | truth P | 反解P | 误差 | 判定 |
|---|---|---|---|---|
| S1 (FF120) | 45 | 28.7 | 36% | ⚠️ FF 偏差（#26） |
| S2 (FF0) | 45 | 44.6 | **0.8%** | ✅ |
| S3 (FF0, P49) | 49 | **59.7** | 22% | ✅ **最高，方向对** |
| S4 (FF0) | 45 | 46.9 | **4.3%** | ✅ |

🔑 **方向验证通过**：S3(P49) 反解最高（59.7 > 44.6/46.9）。
🔑 **FF=0 三段平均 9.0%**；**排除 S3 异常后，S2/S4 平均 2.55%**（优于 2g 吴bbl 8.9%）。

### 4.4 S3 过冲诊断（2m-c，S2 vs S3 完美 P 对照）

S2(P45) vs S3(P49)：同 FF=0/D=30/dmin30，仅 P（45 vs 49）+ I（80 vs 88）不同。

- **✅ K-P 无耦合**：S3 自扫 bestK=80（=S2），交叉验证 S3 bestK 反解 S2 仍准（0.8%）。K 是稳定机械常数。
- **🔑 S3 曲线反物理**：P=49 上升比 P=45 慢（idx80: S3=0.97 未稳态 vs S2=1.01 已稳态），违反"高 P → 高带宽 → 快响应"。最可能：**P=49 触发轻微振荡**（`bf-pid-term-real-physics` "高 P 易震"），stackResponse 跨窗口平均振荡后等效上升变慢。
- **🔑 LM 多局部解**：K=60→P=7.67（RMSE 0.040 最低），K=80→P=59.68（RMSE 0.120），不连续跳跃。反解空间多模态/病态。

S2 vs S3 曲线对比 dump：`/tmp/spbe_s2_s3_curves.txt`。

## 五、三大结论

1. **迭代闭环方向✅验证通过**：飞手升 P（45→49），反解识别为最高。**核心降维（单次精度→方向正确性）在新飞机（第二架、不同机型）上数学成立**，不依赖单次绝对标定。
2. **FF=0 干净精度 2.55%**（S2/S4 平均，排除 S1/S3 异常）——**优于 2g 吴bbl 8.9%**。新飞机泛化不仅方向对，精度更优。
3. **K_plant bestK=80，K-P 无耦合**（S3 交叉验证）。K 是稳定机械常数，但欠定（#27）。

## 六、开放问题（均不阻塞迭代闭环）

### #26 FF=120 通道建模偏差
- **现象**：同 P=45，FF=0 的 S2/S4 反解准（0.8%/4.3%），FF=120 的 S1 偏低 36%（28.7）。
- **根因（推断）**：forward 时域积分里 FF 项把前馈算成"额外 P 贡献"，LM 压 P 补偿。
- **修法待查**：FF 项系数/相位；可能加 FF 低通（header `rc_smoothing_active_cutoffs_ff_sp_thr`=19Hz）。
- **产品影响**：飞手若开 FF，反解推荐 P 会偏低。需校正或提示。

### #27 K_plant 欠定（产品化核心障碍）
- **现象**：K=10（误差 5.8%, RMSE 0.063）和 K=80（误差 0.8%, RMSE 0.113）都接近真值。"最小 RMSE 选 K"失效。
- **产品化障碍**：飞手不知真值，不能用 RMSE 选 K。
- **候选兜底**：① 尺寸/电机 KV → K 先验（3.5寸/1505 → K 档位表）；② 每架飞机预标定一次（飞一段已知 PID 数据，扫 K 定 bestK，存飞机档案）；③ 联立 τM（2k 已证死，不可行）。

### S3 振荡/曲线反物理（模型局限）
- P=49 触发轻微振荡，stackResponse 平均后上升变慢，forward（纯二阶无振荡建模）无法拟合 → P 解偏（过冲）。
- forward 缺振荡建模（高 P 区局限）。非当前主线，进阶优化。

## 七、🔑 构建指导（反解接进 IterationChain 时照此走，不乱猜）

### 7.1 反解参数（2m-b 已验证 bestK=80 配置）

```objc
// 机械常数（新飞机1505/3.5寸标定值，bestK=80）
BFMechConstants *mech = [BFMechConstants withKPlant:80.0  // ← bestK（S2扫描，K-P无耦合验证）
                                              tauM:0.010  // 拍脑袋值（2k独立标死局，未独立标）
                                             dScale:0.0007
                                                dMin:<header d_min>   // filterFromBBLHeader 提
                                            dMinGain:<header d_max_gain>];

// 滤波（真实，从 header）
BFFilterConfig *filter = [self filterFromBBLHeader:header outDMin:&dMin outDGain:&dGain];

// 反解调用（时域 forward，2g 突破配置）
[solver solveFromTargetCurve:target
                initialGuess:guess  // guess.p = header_P × 1.3 扰动初值
               mechConstants:mech
                filterConfig:filter
                     fitMask:PIDReverseFitP | PIDReverseFitD  // ← 集成用 P+D 联立（见 7.2）
                 useTimeDomain:YES  // ← 2g 突破关键
                      length:target.count
                     duration:0.5];  // ← 必须与 normalizedCurve 的 responseDuration=0.5 对齐
```

### 7.2 fitMask 选择（重要，避免踩 2h-a 坑）

| 场景 | fitMask | 理由 |
|---|---|---|
| **集成（产品输出）** | `PIDReverseFitP \| PIDReverseFitD`（P+D 联立）| 2g 突破配置（吴bbl P=8.9%）。2h-a 证伪 P-only（P-only 钉死 D 后 P 承担阻尼误差→偏离，吴bbl 23.1%） |
| **方向快速验证** | `PIDReverseFitP`（P-only）| 2m 系列用此，方向✅ + S2/S4 精度 2.55%。但这是干净 FF=0 数据下的表现，噪声数据会退化 |

⚠️ **2m 的 2.55% 是 P-only 测的**。集成用 P+D 联立，精度需在新飞机上重测对照（2m 未测 P+D）。**集成第一步：跑 P+D 联立版，对照 P-only 的 2.55%**。

### 7.3 反解流程（集成主线）

```
1. 解码 BBL → 指定 session → PIDCSVData（decodeBBLSessionToCSVData）
2. 提归一化曲线（normalizedCurveFromCSVData，稳态=1）
3. 质量门：曲线点 < 200 → 拒（非阶跃/数据差，2l 教训：btfl_all16 RMSE 0.70 垃圾数据反解方向都错）
4. 反解（fitMask 见 7.2，D/FF 可固定 header 真值或联立 fit）
5. 输出：反解 P + CLI 命令（PIDCLIGenerator）
6. 进 IterationChain（每轮：反解→CLI→飞手换参飞→导入新BBL→下轮反解）
```

### 7.4 ⚠️ 已知陷阱（构建时避开）

| # | 陷阱 | 对策 |
|---|---|---|
| 1 | **S1 类（FF=120）反解 P 偏低 36%** | FF 通道建模偏差（#26）。检测 FF 开启时校正或提示用户 |
| 2 | **S3 类（高 P 振荡）反解 P 过冲** | 曲线反物理。加振荡检测（FFT 看高频峰），或限制 P 上界 |
| 3 | **K 欠定，RMSE 选 K 失效** | 每架飞机预标定 K（飞已知 PID 数据扫 K），不能用 RMSE 自动选 |
| 4 | **session 级 PID** | `BBLHeaderParser` 只读第一个 header。多 session 不同 PID 时，truth 从 strings 单独提取 |
| 5 | **CSV 不落宿主 /tmp** | BlackboxDecoder 产 CSV 在模拟器 sandbox tmp。要看 CSV，dump 曲线数据到硬编码 `/tmp/` |
| 6 | **duration 必须=0.5** | normalizedCurve 的 responseDuration=0.5 固定，反解 duration 不对齐会失配 |
| 7 | **guess.p 扰动初值** | 用 header_P × 1.3（或 ×0.7），不能从真值起步（LM 不工作） |

### 7.5 精度预期（产品文案/用户体验参考）

| 数据类型 | 精度 | 说明 |
|---|---|---|
| FF=0 干净阶跃数据 | **2.55%**（S2/S4，P-only） | 方向 100% 对。P+D 联立待测 |
| FF=120 数据 | 偏低 ~36%（#26） | 待修 |
| 高 P 振荡数据 | 过冲 ~22%（S3） | 模型局限 |
| 迭代闭环容错 | 方向对 + 多轮收敛 | 单次精度偏不阻塞（核心降维） |
