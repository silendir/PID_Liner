## 调查记录备忘（2026-10-13~19 排查全记录，开工时逐条对照防漏）

本次升级源自六轮真实迭代排查（`吴飞行迭代/` 六轮 BBL+TXT），开工前必须带在脑子里的全部发现：

1. **六轮参数演化事实**：首轮 67/125/37(AG80) → 2轮大砍至 45/80/30(AG30,飞手手动) → 3~6轮滑块摆动(pi 75↔100/i 100↔133/ppi 75↔100)但 header PID 数值恒 45/80/30
2. **CLI 粘贴不重算 bug（最重要）**：3~6轮滑块存档值变了但等效P增益恒 1.45（实测）——**simplified 重算未触发，四轮飞的全是 2轮参数**。飞手应用方式=CLI 粘贴。机制猜想：重算钩子挂 pids_mode 切换/GUI 事件。**App 蓝牙直写参数必须①绕开 simplified 层（MSP_SET_PID 直写数值）或②强制 OFF→RPY 重切 ③写后回读 diff 闭环**——此条若漏，未来推荐全部白给
3. **"两全其美"真凶 = airmode 未开**（低油门混合器钳制惩罚缓慢动作），非 PID 天花板非 TPA。开 airmode 后用户满意 → **迭代闭环首个真实用户验证通过**
4. **AG=30 是飞手首轮手动从 80 砍的**（TXT 从不包含 AG 命令）；**TPA=D/65%/1350 六轮从未入调整空间**
5. **方法论三组件与判据**（详见方法论 v1 文件）：频带定性(30~150Hz >15% 病灶线)/jitter 粗筛(假信号教训：2轮 4.16 被机动脉冲污染，必须频谱复核)/突变场景计数(AG 前置，六轮全 0=AG 盲区)
6. **数据链缺口**：BBL header 滤波配置(dterm_lpf1_static_hz:75 等)从未注入 CSV（P0 补）；**长飞行 100k 截断已修**(68ff1ac，真机待验：session6 黄线应回归)
7. **显示层坑已修**：副标题 Session 双重+1(68ff1ac)、行数封顶显示(68ff1ac)
8. **六轮最终技术判词**：TPA 无病灶保持现状/机械频段干净/AG 盲区待科目/真凶 airmode——诊断卡的回归验收基准就是这四句

## 对现有代码的影响评估（用户问：是否纯增量？）

**设计目标 = 零改动现有逻辑，纯增量补全**。逐项影响面：

| 改动 | 性质 | 风险 |
|---|---|---|
| 新建 NoiseDiagnosisEngine（P1 全部判据引擎） | 纯新增文件 | 无 |
| 诊断卡/频带条/对照线 UI（P2） | 噪声页**追加**区块，现有频谱曲线不动 | 无 |
| PIDCSVData 加 filterConfig 字段（P0） | 纯新增属性 | 无 |
| CSV 注入函数加滤波行（P0 #1） | **追加**注释行内容，不改既有 5 行 | 低——唯一碰旧函数处，只增不改 |
| 油门分桶频谱（P1 #4） | **设计约束**：在调用侧/新引擎做分桶，**不动 PIDTraceAnalyzer 频谱计算内核**；若实现中发现必须动内核，先报备再动 | 需守约束 |
| 迭代链/5层管线/推荐引擎/蓝牙服务 | **零触碰** | — |

结论：核心算法（5 层管线、频谱计算内核、迭代链、BLE 服务）全部不动；仅有的两处旧文件接触均为追加型，符合"功能已完善、只做补全"的定位。
