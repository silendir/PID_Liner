# PID 低角速度曲线偏差问题分析

> 客户反馈日期：2026-04-18
> 状态：待修复

## 客户反馈

### 现象描述

| 场景 | 结果 |
|------|------|
| 同一文件有 >500°/s + <500°/s | ✅ 曲线准确（与 PID Analyzer、PID ToolBox 对比验证） |
| 全程 <500°/s（缓慢打杆/自稳模式） | ❌ 曲线偏差大，不同飞法产出的数据基本一样 |

客户原话要点：
- 角速度超过 500°/s（黄色曲线段）和低于 500°/s（蓝色曲线段）同时存在时，数据基本准确
- 全程低于 500°/s 时（如自稳模式缓慢打杆），出现很大偏差
- 多次用不同飞法，在低于 500°/s 下飞出来的 PID 曲线数据都基本一样
- 怀疑算法在某些情况下有问题

---

## 根因分析

### 核心原因：维纳反卷积在低信号幅度下失效

整个分析链路：

```
pidInput → Hanning窗 → 维纳反卷积 → cumsum(累积和) → 阶跃响应曲线
```

### 维纳反卷积公式

```
result = IFFT( G · conj(H) / (|H|² + 1/sn) )
```

- `H` = FFT(pidInput)，输入信号的频谱
- `G` = FFT(gyro)，陀螺仪输出的频谱
- `sn` = 信噪比（由截止频率决定，所有窗口共用，固定值）
- `1/sn` = 正则化项（防止除零的噪声抑制）

### 问题机制

分母 `|H|² + 1/sn` 中，谁主导决定了反卷积质量：

| 角速度 | `|H|²`（信号功率） | `1/sn`（噪声项） | 主导项 | 结果 |
|--------|-------------------|-----------------|--------|------|
| >500°/s | 很大 | 固定小值 | `|H|²` 主导 | 正确提取脉冲响应 ✅ |
| <500°/s | 很小 | 固定小值 | `1/sn` 主导 | 退化为固定低通滤波 ❌ |

**低信号时数学推导：**

当 `|H|² << 1/sn` 时：

```
result ≈ G · conj(H) · sn
```

此时反卷积结果被固定的 `sn` 项决定，与输入数据几乎无关。

**这就是为什么不同飞法、不同飞行数据，只要角速度都低于 500°/s，输出曲线都基本一样。**

### 为什么混合数据能工作？

1. 高角速度窗口（>500°/s）的 `|H|²` 足够大 → 反卷积正确提取传递函数 → 黄色曲线准确
2. 低角速度窗口被 `lowHighMask(500)` 分到蓝色曲线组
3. 总体分析结果由高质量的黄色曲线数据主导
4. 客户对比 PID Analyzer / PID ToolBox 验证，结论一致

### 自稳模式（Angle Mode）额外因素

- 当前代码 **没有** 区分 Acro / Angle / Horizon 模式
- Angle 模式下 `rcCommand` 表示目标角度（非角速度），PID 输入公式可能不适用
- 这可能是低角速度偏差的次要因素（需进一步验证）

## 修复方案

### 方案 1：输入归一化（推荐，核心修复）

反卷积前对每个窗口做幅度归一化，消除低/高输入的量级差异：

```
修改前：原始 pidInput → 维纳反卷积
修改后：pidInput / RMS(pidInput) → 维纳反卷积 → 结果 × RMS(pidInput)
```

修改位置：`PIDWienerDeconvolution.m` 的 `deconvolveWithInput:output:cutFreq:` 方法

**原理：** 归一化后所有窗口的 `|H|²` 量级一致，`1/sn` 不再在低幅度时主导分母。

### 方案 2：自适应阈值（辅助改进）

将固定 500°/s 阈值改为基于数据分布的自适应阈值：

```
修改前：lowHighMask(maxInput, 500.0)
修改后：threshold = percentile(maxInput, 70)  // 取70百分位数
```

修改位置：`PIDAnalysisViewController.m:846`

**原理：** 根据实际数据分布自动调整分类边界，避免全低数据时无对比参考。

### 方案 3：信噪比检测（用户体验改进）

对低质量窗口添加警告标识，提示用户数据可信度：

- 当所有窗口 maxInput < 某阈值时，显示警告
- 提示："当前飞行数据角速度较低，分析精度可能受限，建议包含快速打杆动作的数据"
